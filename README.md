# SavingsCalculator — Android, лабораторна робота №1

Навчальний застосунок з дисципліни «Програмування мобільних пристроїв», **варіант №14**. Порівнює річний дохід у гривнях із підсумковою сумою за умови щомісячної конвертації частки доходу в USD або EUR.

## Можливості

- Введення місячного доходу M та частки p зі строгими умовами M > 0 і 0 < p < 1.
- Підтримка десяткової крапки й коми, перевірка порожніх та некоректних значень.
- Вибір USD або EUR.
- Розрахунок 12 окремих щомісячних покупок валюти без проміжного округлення.
- Таблиця результатів, українська локаль і два десяткові знаки при відображенні.
- Темний інтерфейс, бірюзові акценти, українські написи.
- Відновлення введення, валюти та поточного екрана після пересоздання Activity.

## Демонстраційні курси

**Це умовні навчальні значення, а не реальні банківські чи офіційні курси. Конкретний рік не задано.**

| Валюта | C_START, грн | C_END, грн |
| --- | ---: | ---: |
| USD | 40,00 | 42,00 |
| EUR | 44,00 | 46,00 |

Значення централізовано зберігаються у `DemoExchangeRates.java` і можуть бути замінені. Застосунок не отримує курси з мережі.

## Розрахунок

- SY = 12 × M — річний дохід.
- Sc = p × SY — витрати на придбання валюти.
- Ci = C_START + i × (C_END − C_START) / 12, i = 1…12.
- W = Σ(p × M / Ci) — загальна кількість придбаної валюти.
- SH = W × C_END — її гривнева вартість наприкінці року.
- SL = SY − Sc — залишок гривень.
- H = SH + SL — підсумкова сума.
- R = H − SY — фінансовий результат.

Середній курс не підміняє щомісячні розрахунки. Неприпустимі значення та переповнення числового діапазону відхиляються.

## Архітектура

Java + XML, Android Fragments, Gradle Kotlin DSL. Package: `com.example.savingscalculator`.

Маршрут: `HomeFragment → IncomeFragment → CurrencyFragment → ResultFragment → HomeFragment`.

- `MainActivity` реалізує `NavigationCallbacks` і централізовано керує FragmentManager та back stack.
- `NavigationFragment` підключає callbacks у `onAttach()` та звільняє їх у `onDetach()`.
- Екрани створюються через `newInstance()`, параметри передаються через Bundle.
- `IncomeFragment`, `CurrencyFragment` і `ResultFragment` явно зберігають дані у `onSaveInstanceState()` та відновлюють у `onViewCreated()`.
- Поточний екран і back stack відновлює FragmentManager. Activity не створює дублікати відновлених фрагментів.
- `SavingsCalculator` містить чисту розрахункову логіку, `IncomeValidator` — перевірку введення.
- Кнопка «Ок» очищає проміжні екрани з back stack; системна Back повертає на попередній екран.

Основний код і ресурси розташовані у `app/src/main/`, unit-тести — у `app/src/test/`, інструментальні тести — у `app/src/androidTest/`.

## Запуск

1. Відкрийте корінь репозиторію в Android Studio — папку з `settings.gradle.kts`, `app` і `gradle`.
2. Встановіть Android SDK Platform 37 та дозвольте Gradle Sync завантажити залежності.
3. У gradle/gradle-daemon-jvm.properties задано JDK 25 для Gradle daemon. Дозвольте завантаження відповідного toolchain або встановіть JDK 25. Рівень мови Java для коду застосунку — 11.
4. Створіть емулятор або підключіть пристрій із Android API 24 чи новішим. Інструментальні перевірки виконувалися на API 37.
5. Виберіть конфігурацію `app` і натисніть Run.

Проєкт використовує compileSdk/targetSdk 37, minSdk 24, Android Gradle Plugin 9.4.1 і Gradle Wrapper 9.6.0. Версії визначені у файлах проєкту; встановлювати окремий системний Gradle не потрібно. Android Studio створить локальний `local.properties`, який не входить до Git.

Збірка у Windows PowerShell (JAVA_HOME має вказувати на сумісний JDK):

```powershell
.\gradlew.bat assembleDebug
```

## Тестування

Unit-тести:

```powershell
.\gradlew.bat testDebugUnitTest
```

Інструментальні тести з запущеним емулятором або підключеним пристроєм:

```powershell
.\gradlew.bat connectedDebugAndroidTest
```

У macOS/Linux використовуйте `./gradlew` замість `gradlew.bat`.

Unit-тести перевіряють формули, сталі/зростаючі/спадні курси, 12 окремих покупок, перевірку введення та неприпустимі параметри. Інструментальні тести перевіряють навігацію, очищення back stack, повторні натискання та явне відновлення стану з вимкненим автоматичним збереженням View.

Остання перевірка поточної реалізації: збірка успішна, 11 unit-тестів і 4 інструментальних тести на API 37 пройдено. Фізичний поворот, великий системний шрифт і компонування на різних розмірах екрана варто додатково перевірити вручну.

Звіти тестів генеруються локально в `app/build/reports/`. Каталоги збірки, кеші, локальні налаштування та ключі підпису виключені через `.gitignore`.
