# SavingsCalculator — Android, лабораторна робота №2

Навчальний застосунок з дисципліни «Програмування мобільних пристроїв», варіант №14. ЛР2 продовжує застосунок ЛР1: користувач вводить місячний дохід `M`, частку `p` (0 < p < 1), вибирає USD або EUR та отримує результат заощаджень.

## Архітектура

Застосунок написаний на Java та XML з Gradle Kotlin DSL. Package: `com.example.savingscalculator`. Основна навігація побудована на окремих Activity з компонуванням `ConstraintLayout`: `MainActivity → IncomeActivity → CurrencyActivity → ResultActivity`.

Кнопка розрахунку створює унікальний `requestId`, публікує стан завантаження у `CalculationRepository` та запускає `SavingsCalculationService`, що успадковує `IntentService`. Служба читає курси з `app/src/main/assets/exchange_rates.txt`, виконує обчислення через збережений чистий клас `SavingsCalculator` і надсилає стан успіху або помилки до Observer-ів. `CalculationRepository` зберігає стан поточного запиту, доставляє події у головний потік і тримає Observer-и через слабкі посилання. `ResultActivity` підписується у `onStart()` та відписується у `onStop()`.

Системна кнопка Back повертає на попередню Activity. Кнопка «Ок» повертає на головний екран і очищує проміжні екрани.

## Курси валют

Файл `exchange_rates.txt` містить демонстраційні курси USD 40,00 → 42,00 та EUR 44,00 → 46,00. Це умовні навчальні значення, не реальні банківські чи офіційні курси. Файл має формат `валюта,початковий_курс,кінцевий_курс`; його можна замінити без редагування Java-коду.

## Формули

- `SY = 12 × M`
- `Sc = p × SY`
- `Ci = C_START + i × (C_END − C_START) / 12`, для кожного місяця `i = 1…12`
- `W = Σ(p × M / Ci)` — сума 12 щомісячних покупок валюти без проміжного округлення
- `SH = W × C_END`
- `SL = SY − Sc`
- `H = SH + SL`
- `R = H − SY`

Результат показує обрану валюту, вхідні дані, курси та всі показники. Виведення відформатоване українською локаллю з двома десятковими знаками.

## Запуск

Відкрийте кореневу папку проєкту в Android Studio, виконайте Gradle Sync, виберіть емулятор або пристрій Android API 24+ і запустіть конфігурацію `app`. Проєкт використовує compileSdk/targetSdk 37, minSdk 24 та Java 11. Версії Gradle і залежностей уже задані у проєкті.

Windows PowerShell:

```powershell
.\gradlew.bat assembleDebug
```

## Тестування

Unit-тести:

```powershell
.\gradlew.bat testDebugUnitTest
```

Інструментальні тести на запущеному емуляторі або підключеному пристрої:

```powershell
.\gradlew.bat connectedDebugAndroidTest
```

Тести перевіряють формули та валідацію, розбір курсів із текстового файлу, відновлення введення/валюти після пересоздання Activity, а також розрахунок у службі та доставку стану Observer-у.

`IntentService` застарілий у сучасному Android SDK, але застосований тут через пряму вимогу методички. Він запускається з видимої Activity після натискання користувачем, виконує коротке завдання і працює в межах життєвого циклу процесу застосунку; для довгих або гарантовано відновлюваних робіт потрібен був би інший API, що виходить за межі цієї лабораторної.
